System map

What works now

  • Educator interview, one question at a time, with a rationale for each question, follow-ups, materials upload and suggested key ideas
  • Teacher-readable design with provenance tags and visible AI assumptions
  • Revision by direct edit or plain-language request; version history with diffs
  • Approval gate enforced server-side; test mode records synthetic approvals as TEST
  • Build into an immutable experience package; withdrawing a design blocks new sessions
  • Learner runtime: gated Preparation, Practice and Feedback phases, adaptive hints and stretch, refusal to give answers
  • Evidence-grounded feedback with self-assessment, observation versus inference, not-assessed criteria and transfer
  • Educator trace from teacher input to design, evidence and feedback; deterministic replay
  • Crash-safe persistence with session resume across a server restart

What remains

  • Live LLM provider run (needs ANTHROPIC_API_KEY)
  • PDF and DOCX material parsing (text formats only today)
  • Real accounts, rosters and LMS integration (single-tenant, optional shared educator key)
  • Voice and scene images from the reference repository (out of scope for this text-first build)
  • Real-classroom efficacy evidence (none claimed)

Decisions and departures from the paper

D1 departureClean, dependency-free Node implementation instead of extending the reference Next.js repository
The reference runtime depends on the OpenAI Realtime voice API, Google OAuth and a large surface (560 source files) that cannot run or be tested here without credentials. A small text-first system can be fully tested end to end while preserving the paper's commitments. The reference repository was audited and its concepts reused (intake agent, design document, template prompts, mentor/practice/feedback, journal/evidence).
D2 departurePedagogy decisions (evidence, adaptation, phase gating, feedback) are deterministic and rule-based; a model provider only voices character moves
Makes approval meaningful (an approved design fully determines runtime behavior), allows deterministic replay, and prevents goal drift, over-helping and invented evidence by construction. It also lets the system run without credentials.
D3 departureText chat instead of real-time voice
There are no voice credentials, and text is accessible and testable. Voice is the reference repository's modality, not a Primer Contract commitment.
D4 Design = editable educator-level decisions + derived content rebuilt by a pure function
Guarantees that teacher revisions propagate to prompts, challenges, criteria and runtime rules.
D5 departureLook-for keyword evidence with minimum-length, reasoning-under-stretch and refutation checks
A deterministic, explainable substitute for model judgment. Look-fors are shown to and editable by the educator. Known limitation: paraphrases without look-for words are missed, and keyword stuffing is only partly mitigated.
D6 Test mode (PRIMER_TEST_MODE=1) forces every approval to be recorded as a synthetic TEST approval
Synthetic testers can exercise the approval gate without ever producing a classroom approval.
D7 File-based JSON storage with atomic writes and per-record locks
Zero dependencies and crash-safe; enough for single-instance classroom pilots.
D8 departureThe paper's full text was not supplied; the Contract is derived from the build prompt plus the reference repository's whitepaper diagrams and architecture docs
Only the build prompt PDF was available; the paper URL is blocked by the network policy.
