# Primer Contract

Source: Section 3 of the build prompt ("Preserve the Primer Contract"). The paper itself ("Primer: An AI Framework for Instructor-Centered Educational Simulation Creation") was not supplied and could not be fetched from this environment, so this contract is taken from the prompt, cross-checked against the whitepaper diagrams in the reference repository (`docs/whitepaper-diagrams/`). Conformance to the paper proper is **pending**.

| # | Commitment | What it requires |
| --- | --- | --- |
| C1 | Educator authority | Educator goals, content, examples, misconceptions, criteria, constraints and classroom knowledge stay visible and editable. AI recommendations are reviewable. Nothing becomes classroom-approved without explicit educator approval. Synthetic approval is labelled test approval. |
| C2 | Meaningful student work | The learner must retrieve, interpret, explain, decide, diagnose, persuade, advise or revise. The system must not solve the task early or remove productive effort through excessive help. |
| C3 | Preparation, Practice, Feedback | Every completed experience connects preparation (context, prior knowledge), practice (application in a scenario) and feedback/reflection grounded in what the learner did. |
| C4 | Productive friction | Uncertainty, character goals, questions, constraints, consequences and calibrated difficulty make the content necessary. Narrative serves the learning goal. |
| C5 | Goal-bound adaptation | Challenge, support, pacing, character behaviour and feedback adapt to learner evidence while staying inside the educator-approved learning target. |
| C6 | Evidence-grounded feedback | Transcripts, decisions, artifacts and events are preserved across phases. Observation is distinguished from inference. A capability the learner had no fair chance to show is not assessed. |
| C7 | Traceability | An educator or operator can trace how teacher input shaped the design, runtime behaviour, evidence and feedback. |
